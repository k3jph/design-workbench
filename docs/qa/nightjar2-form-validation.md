# Nightjar II local-form validation recovery

This investigation starts from frozen candidate `5138a89fc2956d9019d5bd720c987b8b9e24533b` and covers the existing synthetic contact and sign-up forms, not a new recipe. No values are sent or saved.

## Reproduction and correction

A whitespace-only name sets a custom validity error. If a host script then corrects the name by assigning `.value` without dispatching an `input` event, the previous error remains. In the frozen candidate, native pre-submit constraint validation blocks `requestSubmit()` before the handler can recalculate that stale error: valid corrected text remains visibly present, but the local validation success is never reached. System Chromium reproduced this in both languages and Jekyll, Astro and React. Browser autofill/event behavior varies; this reproduction specifically uses a host script and does not claim every autofill behaves this way.

After enhancement has installed the submit handler, the forms now skip the browser's *pre-submit* validation pass, recompute their custom text constraints inside the prevented submit event, and immediately call the native `reportValidity()`. The explicit call still checks native `required`, email type, password and consent constraints and focuses the invalid control. The native Jekyll/Astro implementation enables this mode only after its handlers are registered; React uses it only after hydration. No-JavaScript or blocked-script forms keep their fieldsets disabled, retain ordinary native validation settings, and expose the existing unavailable explanation. The entered name is not trimmed or rewritten. Direct native `form.submit()` intentionally bypasses submit events and is outside this interaction contract.

## Evidence and limits

`form-stale-validity.mjs` passed the 12 family/framework/root-or-subpath Chromium builds. It checks a stale whitespace error followed by a scripted correction and `requestSubmit`, a scripted invalid message followed by correction, preserved surrounding spaces, real native email/type, required password/consent, password minimum-length and code-pattern failure and focus, successful password/code clearing, reset, no navigation, URL/query/hash preservation, and no-JavaScript/blocked-script fallback. Injected listener-registration failure in the Jekyll and Astro implementations also leaves the form disabled, its fallback visible and native validation settings unchanged. The new focused case is included in the existing disposable multi-form/chat composition regression, which checks independent forms and chats, partial initialization, keyboard, axe and recovery. The full matrix is added as a separate nonpublishing portable-examples CI step. The existing Firefox/WebKit smoke job also invokes the same assertions at root paths using its already-built sites, without repeating their builds; this six-case prebuilt mode passed locally in Chromium, while Firefox/WebKit hosted results remain pending. The default test runs all families/frameworks; optional `NIGHTJAR_TEST_FAMILY` and `NIGHTJAR_TEST_FRAMEWORK` filters accept only documented values. `NIGHTJAR_TEST_PREBUILT=1` selects the root-only prebuilt mode and requires `NIGHTJAR_JEKYLL_ROOT`; `NIGHTJAR_BROWSER` selects the browser engine. The script uses the task-local Ruby/Bundler and `CHROMIUM_PATH=/usr/bin/chromium` for Chromium when Playwright's browser is unavailable.

Example/model checks, strict React types, source-archive and manifest checks passed. The search safety check initially lacked Ruby and then a browser path; it passed unchanged after those documented environment paths were supplied. Firefox/WebKit, manual assistive-technology behavior, actual browser autofill flows and other host interventions require separate evidence. No assertion was weakened and no visual baseline was approved.
