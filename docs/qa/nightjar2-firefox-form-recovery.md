# Firefox form recovery investigation

On the #34 form change at `05d28d4`, a scripted correction of a whitespace-only textarea followed by a pointer activation failed in hosted Playwright Firefox. The original regression required the first retry to validate; this was not resolved by sending Escape.

The headed Firefox diagnostic at [run 41151897326, job 124390078476](https://github.com/k3jph/design-workbench/actions/runs/41151897326/job/124390078476) captured the native UI after correction. Firefox's validation popup remained over the physical button position. DOM hit-testing identified the underlying button, but the popup is outside the document. In [run 41151618508](https://github.com/k3jph/design-workbench/actions/runs/41151618508), a real X11 pointer click at the button position reached no document listener and dismissed that popup; a subsequent pointer click reached the button and validated. The run's `nightjar-firefox-native-ui` artifact contains screenshots with synthetic data. Headless repeated and moved Playwright clicks did not reach document listeners; keyboard activation, `requestSubmit()`, and a separate explicit-blur control recovered. These controls establish why the initial pointer retry could fail; substituting them would not test the requested first-click behavior.

The proposed form change presents a first custom whitespace error as an associated inline alert and focuses its field. It suppresses the native popup only for a submission whose first invalid field has that custom error; other first-invalid native constraints retain native reporting. The normal first pointer retry, script correction without an input event, existing descriptions and invalid-state attributes, mixed native/custom constraints, and reset are exercised by regression tests. The two forms on a page retain independent error IDs. Automated checks do not replace manual screen-reader or other assistive-technology review.
