# Nightjar III portable conformance prototype

This is an **offline-input, bounded static evidence runner**, not a replacement for the workbench browser suites and not proof of conformance, accessibility, visual equivalence or release readiness. It accepts separately maintained implementations at explicit full Git commit IDs and runs builds from fresh `git archive` snapshots with no `.git` directory or dependency on the original checkout at build time. Local Git object reads ignore replacement refs and inherited Git configuration. An isolated bare repository reads the pinned object database without the source repository's untracked `info/attributes`, and system/global attribute files are disabled; tracked `.gitattributes` in the pinned tree still apply to `git archive`. It never fetches a repository or updates a ref. Pinned trees containing symlinks or Git submodules are rejected: their external targets could otherwise escape the recorded snapshot. Supply required sources as separate pinned repositories instead. Each family/framework/base case gets fresh copies of all pinned inputs, so mutations or generated caches from one case cannot become another case's source. Existing worktree changes are ignored by construction. A partial run lists every missing configured family/framework target; `--require-matrix` requires all configured pairs. The default matrix contains the original six pairs.

For package-consumer manifests, `--require-checked-inputs` rejects a declared `inputs` entry without an `input_checks` package identity, version and file hash. The result records whether this option was enabled. It covers only explicitly declared inputs: it does not check that a manifest declares every dependency, that a target repository is a package, or that build commands actually consume the checked bytes. Non-package inputs must use a separate manifest or omit this package-specific option.

The runner executes the manifest's commands as **trusted local code**, with the caller's environment and permissions. It does **not** sandbox those commands or enforce network isolation: an arbitrary build script could access the network or the filesystem. Use only reviewed inputs and commands, do not put secrets in the manifest or command arguments, and use an independently enforced network sandbox if an offline guarantee is required. The runner itself performs no remote fetch. Its browser context disables JavaScript and aborts network requests when inspecting HTML; the build remains a separate trust boundary. There is no remote-fetch mode in this prototype.

## Inputs and invocation

Use Node 24.19, Python 3, Git, tar, the workbench's locked npm dependencies (`npm ci --ignore-scripts`), the language-specific locked build toolchains, and a Playwright browser already installed. The commands below are illustrative: replace paths and commit IDs with the exact local repositories and commits being reviewed. Install the existing locked build dependencies in advance; the runner does not install them automatically. Put the manifest and the new output file outside the source repositories. A result path that already exists is rejected, so an unsuccessful rerun cannot be confused with earlier evidence.

  "repositories": {

```sh
CHROMIUM_PATH=/path/to/chromium node scripts/qa/portable-runner.mjs \
  --manifest /absolute/manifest.json --output /absolute/new-result.json --browser chromium
```

The example Jekyll commits are **local-only rehearsal commits**, not public repositories or a transfer of authority. The fixture pin belongs to the frozen Nightjar II workbench. For Firefox or WebKit use `--browser firefox` or `--browser webkit` with the matching Playwright-managed browser available; `CHROMIUM_PATH` only configures Chromium. `{base}` expands to an empty string or `/preview`; `{baseSlash}` expands to `/` or `/preview/`; `{output}` is a new absolute output directory; and `{source:name}` is the archived snapshot of any named input repository. Commands are argument arrays, run directly without an implicit shell, from the target's archived repository root. A target can use several ordered commands for an offline install, build and consumer harness. The output directory must contain the generated site root, including `examples/<id>/index.html` and the experimental scientific workspace. No command or revision is inferred from a moving branch.

For React and Astro, a **site consumer** of the candidate package must supply all those routes before a gallery target can be added. A library tarball or five-page starter alone is not a 50-example implementation. Include its package and consumer-harness repositories as separately pinned inputs, list additional input names in the target's optional `inputs` array, refer to their archived paths with `{source:name}`, and install/build the package offline using reviewed commands and pre-existing locked caches. Every `{source:name}` in a command must name the primary repository or an explicitly declared input. The report records these declared pins with `declared_input_consumption: not_verified`: commands may ignore them or read from elsewhere, so inspect the commands and resulting artifact independently. A workbench-owned consumer can exercise an independent package, but that is not an independently maintained gallery application. If no suitable consumer exists, leave the target out and report the gap. Do not copy a workbench-specific application into a family repository or treat a successful package installation as 50-route parity. The [framework onboarding guide](nightjar-iii-framework-onboarding.md) describes configurable coverage and the explicitly limited one-route adapter smoke capability; matrix completeness alone does not imply equal capabilities.

An optional `input_checks` object on a target can bind a package's identity and selected archived source bytes before the commands run. For example, `"input_checks": {"react-martlet": {"package_name": "@martlet/react", "package_version": "0.1.0", "files": {"src/index.tsx": "<64 lowercase SHA-256 hex characters>"}}}`. The name must be the target repository or one of its declared inputs. Populate the hashes from an independently reviewed exact source tree; a check against self-selected or untrusted hashes provides no independent provenance. Each checked file must exist and match, and package name and version must match. The checks and hashes appear in the result. This rejects missing, swapped, wrong-version and changed **checked bytes**, not all incompatible behavior, and it cannot establish that a command actually consumes the checked package; `declared_input_consumption` remains `not_verified`.

For an opt-in adversarial integration test, supply local manifests with the existing React and Astro gallery build commands and pinned family inputs: `CHROMIUM_PATH=/path/to/chromium node scripts/qa/portable-input-negative.mjs /absolute/react-manifest.json /absolute/astro-manifest.json`. It makes temporary local clones, removes the React `DataTable` export or Astro `Button.astro` in each family, commits each intentional mutation locally, pins the mutated tree and its matching checksum, and requires the actual gallery build to fail specifically for the missing export/component. It does not change the original repositories or publish anything. Since it changes the expected hashes to match the mutation, a hash-guard rejection cannot masquerade as a consumption test. This probes only these particular exports and these reviewed manifests; it does not prove arbitrary manifest commands consume every input or make the workbench gallery independently maintained.

## What is checked

For each configured family/framework at `/` and `/preview`, the runner checks all 50 canonical route files with JavaScript disabled: one canonical heading and `main`, the canonical summary, section titles and representative structured text, table headers/rows/scope, image alt text, and dashboard fixture names and nonempty tables where applicable. The shared HTML verifier checks local `href`/`src` paths and fragments in every rendered HTML page, rejecting decoded destinations that escape the site root. The separate experimental science route is checked for a heading and static result rows. The output root, its ancestors within the temporary run directory, output symlinks and special files are checked before traversal. The result records the exact repository commits and fixture hashes, commands, Node/browser version, source and verifier hashes, whether the runner checkout was dirty, per-build output-tree hash and per-route static status. Paths and outputs are temporary; the JSON report is written only after every configured case succeeds.

This does **not** validate interaction, hydration, keyboard/focus, interrupted events, JS-blocked behavior, cross-engine parity, visual identity, performance, contrast, axe, screen readers or physical print. It does not fetch external resources, compare all prose or all dashboard states, inspect CSS `url()` dependencies, or certify that a build command consumed the intended package. A 300-cell static inventory means 50 routes × two families × three supplied framework consumers; testing both bases yields 600 route checks. Each status is explicitly `static_content: checked`, not a general pass. The experimental route is tracked separately and is not the 51st canonical example. The 18 Firefox and 18 WebKit incomplete contrast results remain open.

Run `npm run test:portable-runner` for regression tests of pin validation, rejecting moving refs and incomplete matrices, preserving existing result files, and using committed bytes rather than dirty worktrees. Record the exact runner commit and clean/dirty state, manifest, input commits, toolchain, commands and result artifact in the campaign ledger. Continue to run the existing behavior, browser, package, accessibility and archive suites independently.
