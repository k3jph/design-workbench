Neither local repository has a remote. From this workbench review branch, create a fresh, empty parent directory outside the workbench and run `python3 scripts/qa/nightjar-jekyll-rehearsal.py --destination /absolute/existing/empty-parent`. The script reads blobs from the exact frozen commit, verifies regular-file Git modes and source-manifest paths, refuses existing destination paths, and creates local repositories only. It adds seven rehearsal files to each tree: build and verification scripts, the original link checker, an explicit archive allowlist, file-level provenance, standalone instructions and an **inactive** read-only CI proposal. It prepends context notices to the root and archetype READMEs so their workbench-only paths are not mistaken for local instructions; each `nightjar/PROVENANCE.json` records source blob and SHA-256, snapshot SHA-256, and the transformation for every export path. The rest of the export bytes are unchanged. A separate repeat materialization produced the two tree IDs above exactly; Git commit IDs can vary with local commit metadata, so pin and review the actual commit as well as the expected tree.

An optional `--source-commit <full-40-character-sha>` selects a different **locally present, explicit descendant** of the frozen baseline; no remote fetch occurs. The script rejects moving refs, non-descendants, dirty Jekyll source/export paths and occupied outputs. This makes a later reviewed fix an explicit input, not an automatic update of the baseline snapshots. The source commit itself is included in each new candidate's provenance and README.

Each candidate contains its own locked Gemfile, family shell, fonts, notices and 50 examples plus the experimental scientific workspace. The independently sourced family identities remain distinct. Shared catalog, fixtures, contracts and generator retain workbench authority; the copies are snapshots, and no automated bidirectional sync exists. Current `_layouts/default.html`, `_config.yml` and `index.md` remain seeded in-place transformations in `sync.py`, not proven from-scratch inputs. The workbench currently does not automatically prune stale exported pages when a catalog ID disappears. Both points require explicit ownership and deletion-policy decisions before any cutover. The existing shared Jekyll model path is also consumed by Astro and React; it cannot be removed before a reviewed replacement.

The per-file provenance records distinguish the exact exported blob from its upstream input. For the generic export-or-copied-contract category, the six `docs/archetypes/*.md` documents are copied from the matching `examples/page-archetypes/*.md`; `docs/archetypes/contracts/{catalog,dashboards}.schema.json` comes from `examples/page-archetypes/contracts/`. The two upstream source-shell contracts are separately attributed and hashed in `_data/shell.json`. Remaining family export assets, locks, notices and shell files remain tracked at `examples/jekyll/<family>/` in the frozen workbench; their eventual family owner and individual upstream derivation must be reviewed rather than inferred from the export. This record deliberately does not claim the generated export itself is independently authoritative.

## Verified locally

On Ruby 3.2.3, Bundler and the pre-provisioned locked gems at `/workspace/nightjar/toolchains/gems`, `BUNDLE_FROZEN=true bundle install --local` and `python3 nightjar/verify.py` passed for each exact candidate head. The standalone verifier copies the manifest-listed source into a temporary directory without `.git` and without a workbench checkout, then checks:

- Root and `/preview` Jekyll builds and rendered local links/fragments.
- A complete allowlisted source ZIP, no unlisted synthetic private files in the site or ZIP, identical archive bytes across repeated root/subpath builds, and a build from the extracted archive without Git metadata.
- A `--safe` build and malicious Markdown/HTML: the regular renderer strips dangerous script/event content, and the safe-mode fallback leaves it escaped.
- Rejection of a manifested symlink, missing file and manifest traversal before Jekyll can build.

`strace -f -e trace=network` over each full standalone verification and each `bundle install --local` recorded no socket, connect or send syscalls. This is **observed** no-network behavior with cached dependencies, not an enforced offline sandbox: `unshare --net` was denied by the environment, and no fresh dependency installation without a cache was tested. Root/subpath builds need the already installed locked gems; ordinary local Jekyll builds do not contact or check out the workbench. CI proposal text was not activated or run on a hosted service.

The separate fast `python3 -m unittest scripts.qa.tests.test_jekyll_rehearsal` passed: two fresh materializations had identical trees, both had no remote, provenance matched the frozen Git blobs and snapshot bytes, manifest and tracked file sets matched, and a repeat into an occupied destination failed without overwrite. `/workspace/nightjar-iii/jekyll-martlet.patch` and `jekyll-krigsvold.patch` export the local three-commit histories with binary content. Applying each to a fresh empty local Git repository reproduced the recorded tree; Git reported two inherited blank-line-at-EOF whitespace warnings per patch. The patches and local candidate directories are review artifacts, not published packages or archives.

The materializer regression also rejects a moving ref, a non-descendant and a deliberately dirty source in a disposable clone, before creating outputs. ## Provenance, update and rollback decisions

An attributed snapshot is the defensible rehearsal here: a path-only history split of the generated export would omit the causal history of the shared Jekyll generator, fixtures, catalog and overlays. Each snapshot instead includes file-level immutable blob/source mappings and retains original license, NOTICE, font and source-shell files; human review must determine license sufficiency and whether a history-filtering alternative is warranted. The new `nightjar/` helper files originate in this Nightjar III workbench review branch, not in the frozen baseline.

For a future update, pin a newly reviewed workbench commit, classify every path's authoritative input and owner, regenerate snapshots into **new** empty local directories, review the file-level diff, licenses, shell hashes and stale-page policy, and run the standalone/archive and independent paired conformance suites. Never overwrite an existing candidate or move authority implicitly. A future approved handoff requires named maintainers, frozen fixture/contract update rules, source ownership for every shared/seeded file, repository visibility and branch controls, and independently verified read-only CI. Retain the workbench's present sources, reviewed commits, local trees and patches until the new owners and conformance gates are approved. If any verification or handoff fails, keep the existing workbench source authoritative and discard the rehearsal rather than attempting a partial migration.

Creating or populating `martlettheme/jekyll` and `krigsvoldtheme/jekyll`, moving authority, modifying production controls, publishing artifacts, and deploying are separate decisions requiring explicit authorization. A workbench main merge can invoke reference release and downstream adoption/deployment; the Nightjar II publication proposal is not active protection. Do not use these rehearsal results as permission to perform any of those actions.
