# Nightjar architectural findings

Review baseline: workbench `ea5a180` on 29 October 2026. This report separates established behavior, review findings and proposed requirements. It relies on source inspection and the bounded runs recorded in the [progress ledger](nightjar-status.md), rather than presenting those runs as new tests. The [conformance snapshot](nightjar-conformance.md) is dated and records evidence per route; its 300 cells do not certify full behavior, accessibility, visual parity or performance. The experimental scientific workspace is outside the 50-recipe matrix at this baseline.

## Design-language identity and authority

The families share native semantics and functional acceptance criteria, but their source-informed visual decisions remain independent. The Martlet guidance emphasizes the relationship between field, group and region; a reading sequence and a bounded prose measure; Lato for interface work, Cambo for prose and selective Cinzel. The Krigsvold guidance emphasizes named regions, stable alignment and efficient local density with Roboto and the existing navy, glacier, paper and bronze roles. Either may use a focused page, top navigation or side navigation when the task warrants it. Neither family is defined by an obligatory sidebar or a palette substitution.

The available offline guidance identifies grammar 0.3 as experimental, not a stable release: Martlet's source profile points to `k3jph/k3jph.github.io` at `32b7166a629ea696147d0d779d911b713e4baf7e`; Krigsvold's points to `basuhoward/krigsvold.org` at `a3cf072c516c59ed35814e0fa153028cc91ceecd`. It identifies experimental React 0.1.0 against core 2.1.0 and separate core/Astro 2.2.1/1.2.1 snapshots. These are guidance provenance, not verification of package publication or of the current workspace implementation. The design MCP tools were not available in this review. Source site objects, contextual translations and new application extensions should remain distinguishable; a token or passing test alone does not establish source fidelity.

The visual sweep described in the ledger captured 516 images, checked overflow, asset and browser errors, and compared selected heading roles. It found actionable card/action and heading inconsistencies (`c39a3e6`). Later checks found missing section indexes (`6a24895`) and breadcrumbs (`0531774`). These corrections improve identifiable source anatomy, but screenshots are evidence for the inspected cases, not approved baselines or a complete aesthetic review. Different language compositions are permitted; functional and semantic gaps require a reason or correction.

## APIs, tokens and coupling

The two workspace React entry points expose a corresponding component set, including `Field`, `Dialog`, `Pagination`, `Tabs`, `ErrorSummary`, `DataTable` and `AppShell`. Their near-parallel implementation makes behavior drift possible: a repair to native dialog or focus behavior must be made and tested in both. The current paired consumer tests are useful evidence; creating a new shared package is not justified solely by textual duplication, because family styles and evolution remain separate. Reconsider extraction only with a concrete maintenance benefit, compatibility plan and cross-family tests.

The example adapters use shared semantic roles (`--ex-*`) mapped to each family's source roles, while React uses family component classes. This permits the same semantic state to have distinct native expression. It does not prove token completeness in every surface or contrast state: the caption, dark document index, button transition and scrolling header defects were all found only in particular contexts. Audit foreground/background pairs, focus and unavailable states in their actual cascade, including gradients, rather than declaring a token safe by name.

The catalog, shared fixtures, schema, domain calculations and test assertions are appropriate shared boundaries. Renderers, source layouts and controller state are framework-specific. The portable Jekyll source archive uses an explicit source manifest; adding a source file requires the existing manifest workflow. Archive inclusion does not prove that allowlisted text contains no secrets. The scientific specimen shares a calculation model and shows draft/result separation, but is experimental and does not establish validated engineering calculations or broad application parity.

## Prioritized follow-through

1. Finish and independently check scientific routes/navigation and actual CSV behavior in all six family/framework combinations, including root/subpath and script-unavailable cases. Keep it outside the canonical 50 until promotion has an explicit contract and evidence.
2. Complete hosted required checks on the reviewed head; distinguish a cancelled superseded run from a failing test. Review Firefox/WebKit incomplete contrast nodes with appropriate tools and record manual assistive-technology and genuine zoom findings separately.
3. Review representative same-family pages and states across frameworks at narrow and wide sizes, including focused/invalid, dialog, filter, no-result and failed-update states. Compare to each family's source treatment, not to the other family for pixel equality.
4. Test public React components as packed consumers in all supported engines and record migration implications, including `Field` helper IDs and React multi-root `identifierPrefix`. Do not imply workspace changes have already shipped.
5. Audit remaining semantic token pairs and real transitions in their actual surfaces; document source-derived roles versus application extensions. Preserve usable focus, labels and dense table scrolling as text enlarges.
6. Extend contracts only when an example demonstrates the need: independent confirmation, unsaved-draft navigation, asynchronous cancellation and durable service behavior require tests and real service boundaries before a production claim. Record remaining framework differences and keep the matrix evidence dated.

This is an architectural review at the named baseline, not an approval to merge, publish, release or create repositories. Security triage, stacked-PR review and a Jekyll extraction plan are separate workstreams.
