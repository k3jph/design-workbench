## Reproduce local React/core rehearsal

Provide the two standalone React source repositories at their pinned local commits and the exact core tarballs. The output directory must not exist. `npm ci --offline` needs a populated cache; commands are not a network sandbox.

```sh
node scripts/nightjar3/core-react-rehearsal.mjs MARTLET_REACT_REPO KRIGSVOLD_REACT_REPO MARTLET_CORE_TGZ KRIGSVOLD_CORE_TGZ NEW_OUTPUT
NIGHTJAR_REACT_ARCHIVE_DIR=NEW_OUTPUT NIGHTJAR_CORE_ARCHIVE_DIR=NEW_OUTPUT NIGHTJAR_REACT_ARCHIVE_VERSION=0.2.0 PLAYWRIGHT_EXECUTABLE_PATH=/usr/bin/chromium npm run test:dialog-consumer
# Repeat test:pagination-consumer, test:error-summary-consumer, test:fields-consumer and test:tabs-consumer;
# the same environment applies to node scripts/nightjar3/test-packed-shell-table.mjs.
NIGHTJAR_REACT_ARCHIVE_DIR=NEW_OUTPUT NIGHTJAR_CORE_ARCHIVE_DIR=NEW_OUTPUT PLAYWRIGHT_EXECUTABLE_PATH=/usr/bin/chromium node scripts/nightjar3/test-core-react-bases.mjs
```

`test-core-react-bases.mjs` accepts `NIGHTJAR_REACT_LANE=theme` with a directory containing the legacy React 0.1.0 candidate and published theme 2.1.0 tarballs. It installs each lane separately and rejects the other identity in that consumer. React JS and declarations remained byte-identical to the extracted candidate; the CSS imports are deliberately changed. In the checked artifacts, theme 2.1.0 versus core 2.2.x `theme.css` and `foundation.css` were byte-identical; `tokens.json` differed in its version field. This is not a full visual regression or a claim all CSS and data are identical across versions.

## Source site and contrast findings

Both source-site candidates were installed locally from the original reviewed core and Astro tarballs, with no `/theme` top-level package. Their unit tests and direct root Astro builds passed. The immutable source-shell styles retain their historic paths; a narrow build-time CSS path mapping points the one legacy stylesheet reference at the byte-equal core export without claiming that npm peers are interchangeable. This is a local rehearsal, not a complete source-site migration: root-relative links fail subpath verification, full `npm run build` is blocked fetching its checksum-pinned GitHub React reference, registry lockfiles are unresolved and published data/agent metadata require review. Existing published `/theme` guidance is preserved where it describes the public release.

The initial hosted Martlet Astro 5/Chromium check failed its actual axe color-contrast assertion on the submit button. The original core tarballs preserve a known disabled-to-enabled background transition that can temporarily reduce contrast. Separate [Martlet core contrast PR](https://github.com/martletdesign/core/pull/9) and [Krigsvold core contrast PR](https://github.com/krigsvolddesign/core/pull/10) apply the previously reviewed Nightjar fix; only `dist/components.css` changes in each derivative tarball, so these hashes differ from the original pinned core migration candidates. The Astro verification branches now pin the corrected derivatives. Do not regard the original and corrected tarballs as interchangeable. Follow-up hosted cross-browser results and the decision to integrate the core fix remain explicit gates.
