The archive matrices exercise the five-page starter in Chromium, Firefox and WebKit at root and `/preview`, with automated accessibility checks and JavaScript-disabled navigation. They are not a complete reference-site, real-device or manual assistive-technology assessment. The local two-version rehearsal created an Astro 2.0.1 test snapshot while retaining the Astro 2.0.0 snapshot and core 2.2.3/2.2.4 pins, without changing the latest pointer. It used disposable local repositories, not production tags.

Both existing core package tarballs matched their previously reviewed bytes and their npm signature/attestation provenance was verified on GitHub-hosted runners. The existing Martlet Astro 1.2.2 provenance was also verified against its historical `martlettheme/astro` release identity. The registry did not advertise provenance for the historical Krigsvold Astro 1.2.2 package. The proposed new tag-push OIDC publication and its provenance shape have not been tested by an actual publication. A local npm signature audit could not reach the Sigstore trust-root service (HTTP 403); the corresponding hosted checks passed.

Core and Astro proposed trees atomically remove their legacy release-event publisher while retaining their tag workflows disabled. Current main branches are unchanged. Core's existing staged path remains separate. Astro's combined tree requires a documentation matrix and calls a deliberately failing remote immutable-store verification stub before any npm publication. Local exclusive directory creation and a caller-supplied baseline digest do not prove remote immutability. Authenticated baseline retrieval, durable create-only remote archive storage, independent remote byte verification, serving historical URLs, and tested latest-pointer promotion/rollback must be designed, implemented and reviewed before replacing that stub or enabling the tag workflow. See [the contract](versioned-docs-contract.md) and [administrator checklist](gitflow-administrator-checklist.md).
