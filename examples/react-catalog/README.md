# React catalog: partial paired implementation

This experimental workbench example uses the existing `@martlet/react` and `@krigsvold/react` workspace packages and the shared `page-archetypes/content/catalog.json`. It prerenders all 50 catalog records and an index for each family, then hydrates React-controlled archive pagination and the three dashboards. Both families use their own `Article`, `DefinitionList`, `DataTable`, `Disclosure` and `Pagination` components and theme 2.1.0, inside a contextual source-informed React shell. Build-time family selection keeps the other family's CSS and fonts out of the build.

Run from the workbench root with Node 24 and the locked dependencies. The shared framework-neutral Markdown renderer uses the workbench's locked parser dependencies; it is executed during build, not bundled into the React client.

```sh
npm ci --ignore-scripts
npm run build --workspaces
NIGHTJAR_FAMILY=martlet node examples/react-catalog/build.mjs
NIGHTJAR_FAMILY=krigsvold NIGHTJAR_BASE=/preview/ node examples/react-catalog/build.mjs
CHROMIUM_PATH=/usr/bin/chromium node examples/react-catalog/test.mjs
CHROMIUM_PATH=/usr/bin/chromium node examples/react-catalog/test-integrated-dashboards.mjs
CHROMIUM_PATH=/usr/bin/chromium node examples/react-catalog/test-source-shell.mjs
npx tsc --ignoreConfig --noEmit --allowJs --jsx react-jsx --module esnext --moduleResolution bundler --target es2022 --types vite/client,node --resolveJsonModule --skipLibCheck --strict examples/react-catalog/src/*.tsx examples/react-catalog/src/*.ts
```

The three dashboards use a separate client entry with route-split application chunks; ordinary content pages do not load those chunks. Gallery, workspace, chat and simulations load an interactive chunk only on their own pages; their styles are included in server-rendered HTML. Dashboard navigation works without JavaScript; the corresponding route stylesheet and data tables are present before hydration. Analytics and operations charts start with a compact SVG layout so labels remain legible before hydration and expand to the available width when enhanced; exact values remain in their data tables. To enable cross-family comparison, set `NIGHTJAR_PEER_URL` at build time to the other deployment’s absolute HTTP(S) base. No public destination is assumed.

The build emits real route HTML at `dist/<family>/examples/<id>/`; no server-side SPA fallback is needed for these routes. HTML is present with JavaScript disabled. Archive pagination progressively enhances after hydration: without JavaScript or in print, every record is visible. Navigating to the first or last page restores focus to the available button. Structured destinations, Markdown links and fixture SVGs are base-aware; the build rejects unsupported section kinds rather than silently dropping them. Article author, date and subjects, and event start/end, timezone, location and registration state are retained. Tables use the native family DataTable with a named scrolling region and semantic headers; figures retain the fixture's alt text and captions. The build compiles checked-in Markdown with raw HTML disabled except for the stress fixture, where the shared renderer applies a narrow HTML/MathML allowlist. This is not an untrusted-content ingestion API; no general HTML sanitization claim is made. The report CSV is copied from the shared fixture.

Reading and document recipes include a native section index, matching the Jekyll examples. Its fragment links work without JavaScript and the index is omitted in print.

The Chromium test covers both families at `/` and `/preview/`, every implemented route's titles, section headings, structured links, figures and tables, CSS isolation, resource loading, 320px overflow, representative 1440px overflow and automated axe checks, keyboard pagination and focus recovery, reload, print and no-JavaScript visibility. It also exercises Markdown structure and allowlist safety, article metadata, event context, native disclosures, search, local form validation and sensitive-field clearing, gallery keyboard/focus behavior, local workspace and chat operations, simulated station and scene controls, and generated local destinations. Search and form controls are disabled before hydration, so no-JavaScript output cannot accidentally submit values.

**All canonical routes are present, but this is not a claim of full parity.** Cross-framework visual and behavioral comparison remains incomplete, including comprehensive checks of the dashboards and each example state. The recovery pages illustrate content but do not configure actual HTTP error status. The shared React shell uses each family’s original mark and source-informed masthead, grouped footer and mobile navigation; its fictional-host content is contextual and does not reproduce the original owner’s footer identity. Krigsvold landing, dossier, detail and collection labels align with their content, while Martlet retains its editorial sequence. The shell is not a byte-identical site port: the reading masthead remains contained rather than full-bleed, breadcrumb position differs, and complete source-site navigation and footer destinations are not reproduced. Full visual parity with Jekyll or Astro is not established. Further family composition, dark-mode, internationalization, screen-reader and cross-browser review remains open. The React packages and layout translation remain experimental. Do not deploy this incomplete slice as a complete example site.
